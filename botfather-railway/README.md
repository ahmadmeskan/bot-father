# 🤖 ربات‌ساز تلگرام (Bot-of-Bots) با Pyrogram

یک **ربات مادر** که کاربران فقط توکن می‌دهند و ربات فرزندشان بلافاصله ساخته و اجرا می‌شود — بدون ری‌استارت کردن پروژه.

---

## ✨ امکانات

**ربات مادر**
- ساخت ربات با گرفتن توکن + اعتبارسنجی خودکار توکن
- پنل مدیریت اینلاین برای هر ربات (روشن/خاموش/حذف)
- سقف تعداد ربات برای هر کاربر، کانال عضویت اجباری، پنل ادمین و آمار کلی
- 📝 **پنل متن‌های ربات**: تغییر هر ۸ متن ربات فرزند (خوش‌آمد، عضویت اجباری، وظیفه، پیام پایانی، پیام مسدودی، راهنمای منو، پشتیبانی) با بازگشت به پیش‌فرض
- 👥 **مدیریت کاربران**: آمار، لیست مسدودشده‌ها با تاریخ و نام، مسدود/رفع‌مسدود و **جستجوی عضو با آیدی عددی، یوزرنیم یا نام**

**ربات‌های فرزند**
- پیام خوش‌آمد قابل تنظیم با متغیر `{name}` و `{id}`
- **دکمه‌ی چندمحتوایی**: هر دکمه می‌تواند هم‌زمان متن، چند عکس، ویدیو، فایل و صوت داشته باشد
- ویزارد ساخت دکمه روی یک پیام واحد که خودش را به‌روز می‌کند (بله/خیر برای هر نوع)
- انتخاب اینکه متن به کدام رسانه به‌عنوان کپشن بچسبد — متن دقیقاً یک بار ارسال می‌شود
- پیش‌نمایش دکمه قبل از انتشار
- کانال عضویت اجباری با دکمه «عضو شدم»
- پیام همگانی (broadcast) با گزارش زنده و حذف خودکار کاربران بلاک‌کننده
- ✉️ **پیام به کاربر خاص**: ارسال متن/عکس/فایل از پنل مالک به یک کاربر مشخص (با کلاینت خود ربات فرزند)
- 👥 **زیرمجموعه‌گیری به‌ازای هر دکمه**: هر کاربر لینک دعوت اختصاصی می‌گیرد؛ هر دکمه از پنل می‌تواند جداگانه قفل دعوت بخورد یا نخورد و **تعداد لازم برای هر دکمه جدا تنظیم می‌شود** (مثلاً دکمه A شش دعوت، دکمه B یکی). استارت کاربر هرگز به‌خاطر دعوت مسدود نمی‌شود؛ پیام دعوت با **عکس و متن قابل تنظیم** + متغیرهای `{name} {id} {link} {button} {count} {done} {left}`
- سیستم پشتیبانی: پیام کاربر → مالک ربات، پاسخ با **ریپلای**
- 🏁 **پیام پایانی**: یک پیام کلی که بعد از محتوای **هر دکمه** برای کاربر می‌رود (قابل ویرایش/حذف)
- 🤜 **وظیفه اجباری (نسخه‌ی جدید — بدون تأیید)**: برای دریافت فایل، اول پیام «خواسته» (مثلاً عضویت در کانال) برای کاربر نمایش می‌شود؛ **هر ۲۴ ساعت برای هر کاربر** تکرار می‌شود و بعد از **تاخیر قابل تنظیم (پیش‌فرض ۱۵ ثانیه)** فایل خودکار ارسال می‌شود. دیگر نیازی به ادمین‌بودن ربات در کانال نیست چون هیچ تأییدی انجام نمی‌شود
- ⛔️ کاربران مسدودشده هیچ محتوایی نمی‌گیرند (حتی `/start`)
- 📊 **آمار کامل ربات**: آمار کاربران (کل/فعال/غیرفعال + ورودی‌های ساعت/۵ساعت/روز/هفته/ماه)، آمار دموگرافیک (میانگین سنی و توزیع جنسیت)، آمار فایل‌ها (تعداد/بازدید/لایک/دیسلایک) و **مشخصات ربات** (آیدی، مالک، وضعیت، حذف خودکار، پسورد، وظیفه، رندوم، سرچ)
- 🔗 **راستی‌آزمایی آمار**: همه‌ی عددها مستقیم از دیتابیس دوباره شمرده می‌شوند و سازگاری‌شان با هم بررسی می‌شود (رکورد یتیم، شمارنده‌ها، سلامت DB، هویت زنده‌ی ربات)
- 👍👎 **لایک/دیسلایک و 👁 بازدید**: زیر محتوای هر دکمه دکمه‌ی رأی می‌آید؛ هر کاربر یک رأی (قابل تغییر/برداشتن) و هر ارسال یک بازدید
- 🎂 **سن و جنسیت (اختیاری)**: از کاربران جدید برای آمار دموگرافیک پرسیده می‌شود (قابل خاموش‌کردن)
- 🔑 **پسورد فایل‌ها**: کاربر باید یک‌بار رمز بفرستد تا محتواها باز شود؛ تغییر رمز همه را دوباره قفل می‌کند
- 🎲 **فایل رندوم**: دکمه‌ای در منو که یکی از فایل‌های قابل‌دسترس کاربر را تصادفی می‌فرستد (دکمه‌های قفل‌دارِ بازنشده حذف می‌شوند)
- 🔍 **جستجوی فایل**: جستجو در عنوان و متن دکمه‌ها با نتایج اینلاین
- 🗑 **حذف خودکار**: محتوای دکمه‌ها بعد از N ثانیه خودکار پاک می‌شود
- اطلاع‌رسانی کاربر جدید به مالک، ذخیره کاربران در SQLite

## 🚀 راه‌اندازی

```bash
cd botfather
pip install -r requirements.txt
cp .env.example .env      # سپس مقادیر را پر کنید
python main.py
```

### مقادیر `.env`

| متغیر | توضیح |
|---|---|
| `API_ID` / `API_HASH` | از [my.telegram.org](https://my.telegram.org) → API development tools |
| `MOTHER_TOKEN` | توکن ربات مادر از [@BotFather](https://t.me/BotFather) |
| `ADMINS` | آیدی عددی ادمین‌ها با کاما (از [@userinfobot](https://t.me/userinfobot)) |
| `FORCE_CHANNEL` | کانال اجباری ربات مادر (اختیاری) |
| `MAX_BOTS_PER_USER` | سقف ربات هر کاربر (پیش‌فرض ۳) |
| `LOG_TOKEN` | توکن ربات گزارش‌گیر خطا (اختیاری، از @BotFather) |
| `LOG_CHAT` | آیدی عددی چتی که گزارش‌ها به آن می‌رود |

> فقط یک `API_ID/API_HASH` لازم است؛ همه ربات‌های فرزند از همان استفاده می‌کنند.

ربات‌ها بعد از ری‌استارت پروژه به‌صورت خودکار دوباره اجرا می‌شوند (اگر خاموش نشده باشند).

## 🛠 اجرای دائمی (systemd)

ساده‌ترین راه — اسکریپت خودکار (پکیج‌ها، کاربر اختصاصی، venv، سرویس):

```bash
sudo bash deploy.sh          # نصب کامل روی سرور
bash deploy.sh --dry-run     # فقط بررسی، بدون نصب
```

یا دستی — فایل `botfather.service` را در `/etc/systemd/system/` بگذارید:

```ini
[Unit]
Description=Telegram BotFather
After=network-online.target
StartLimitIntervalSec=300
StartLimitBurst=10

[Service]
User=botrunner
WorkingDirectory=/opt/botfather
ExecStart=/opt/botfather/venv/bin/python main.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

سپس: `sudo systemctl daemon-reload && sudo systemctl enable --now botfather`

- بعد از کرش: ظرف ۱۰ ثانیه دوباره بالا می‌آید (`Restart=always`)
- بعد از ری‌بوت سرور: خودکار اجرا می‌شود (`enable`)
- لاگ زنده: `journalctl -u botfather -f`
- حداکثر ۱۰ کرش در ۵ دقیقه؛ بیشتر از آن سرویس قفل می‌شود (جلوگیری از crash-loop بی‌پایان)

### 📨 گزارش خطا به تلگرام

در `.env` مقداردهی کنید:

```env
LOG_TOKEN=…   ← توکن یک ربات جدا برای گزارش‌ها (از @BotFather)
LOG_CHAT=…    ← آیدی عددی خودتان
```

- هر ERROR/CRITICAL (کرش، خطای هندلرها) فوراً به تلگرام می‌رود — مستقل از Pyrogram، پس حتی اگر خود ربات بمیرد گزارش می‌رسد
- استارت/خاموشی تمیز هم اطلاع داده می‌شود
- ضد اسپم: خطای تکراری حداکثر یک‌بار در ۳۰ ثانیه
- تست اتصال: `python -c "import tglog; print(tglog.check())"`

## 🩺 عیب‌یابی

### ربات بالا می‌آید، لاگ تمیز است، ولی به `/start` جواب نمی‌دهد

علت تقریباً همیشه **ناسازگاری event loop** در پایتون ۳.۱۲+ (به‌ویژه ۳.۱۴ در ترموکس) است.

Pyrogram 2.0.106 در `client.py:299` هنگام ساختِ `Client` می‌نویسد `self.loop = asyncio.get_event_loop()`.
اگر قبل از import یک لوپ دستی بسازید ولی بعد برنامه را با `asyncio.run()` اجرا کنید،
یک لوپ *دوم* ساخته می‌شود؛ کلاینت به لوپ اول چسبیده و دیسپچر هیچ آپدیتی پردازش نمی‌کند →
**اتصال موفق، لاگ سالم، سکوت کامل.**

فایل `compat.py` این را حل می‌کند: یک لوپ واحد می‌سازد و کل برنامه را روی همان اجرا می‌کند.
پس دو قانون:

1. `import compat` باید **اولین** import هر فایلی باشد که pyrogram را صدا می‌زند.
2. به‌جای `asyncio.run(main())` بنویسید `compat.run(main())` و به‌جای `pyrogram.idle()` از `compat.idle()`.

تست سریع سلامت لوپ:

```bash
python -c "import compat, db; db.init(); from mother.bot import app; \
import asyncio; print('match:', app.loop is compat.LOOP)"
```

باید `match: True` چاپ شود.

روی حافظه‌ی مشترک، SQLite گاهی قفل فایل نمی‌گیرد:

```bash

```

### کاربر پیام «ربات موقتاً در دسترس نیست» می‌گرفت

وقتی ربات نمی‌توانست عضویت را بررسی کند (مثلاً ادمین نبودن در یکی از کانال‌ها)،
پیام گنگی به کاربر نشان داده می‌شد. حالا در این حالت هم **همان پیام عضویت**
با دکمه‌ی ورود به کانال نمایش داده می‌شود و هشدار فنی فقط به مالک ربات می‌رود.

### کاربر بعد از خروج از کانال هنوز می‌توانست استفاده کند

نتیجه‌ی بررسی عضویت ۴۵ ثانیه کش می‌شد. حالا پیش‌فرض `check_ttl = 0` است،
یعنی **هر پیام** واقعاً از تلگرام پرسیده می‌شود و خروج از کانال بلافاصله
دسترسی را قطع می‌کند.

### پیام عضویت اجباری قابل تغییر است

از پنل ربات مادر: «📢 کانال‌های اجباری» → «✏️ متن پیام عضویت».
متغیرها: `{name}` `{id}` `{count}` `{channels}` `{links}`
دکمه‌های ورود به کانال خودکار زیر پیام اضافه می‌شوند.

### عضویت اجباری روی من (سازنده‌ی ربات) اعمال نمی‌شود

این عمدی بود ولی گیج‌کننده: مالک ربات از بررسی معاف بود.
حالا **پیش‌فرض خاموش** است و در منوی «📢 کانال‌های اجباری»
دکمه‌ی «معافیت خودم از عضویت» برای روشن/خاموش کردنش وجود دارد.

### دکمه‌های عکس/ویدیو/فایل جواب نمی‌دهند (ولی متن کار می‌کند)

این باگ برطرف شده. علتش یک قانون مهم تلگرام بود:

> **`file_id` مخصوص همان رباتی است که فایل را دریافت کرده.**
> `file_id` ای که ربات مادر می‌گیرد، برای ربات فرزند بی‌اعتبار است.

راه‌حل پیاده‌شده در `media.py`:

1. ربات مادر فایل را در `data/media/<bot_id>/` **روی دیسک ذخیره** می‌کند.
2. ربات فرزند بار اول از روی دیسک آپلود می‌کند.
3. `file_id` حاصل (مال خودِ ربات فرزند) در جدول `file_cache` **کش** می‌شود
   تا دفعات بعد بدون آپلود مجدد ارسال شود.

### پیام همگانی ارسال نمی‌شد

هم برطرف شد. قبلاً پیام با **کلاینت ربات مادر** کپی می‌شد،
در حالی که ربات مادر اجازه‌ی پیام دادن به کاربرانی که آن را استارت نکرده‌اند ندارد
(`PEER_ID_INVALID`). حالا محتوا به یک «بسته» تبدیل می‌شود و
**خودِ ربات فرزند** آن را می‌فرستد. مدیریت `FloodWait` هم اضافه شد.

### هنگام حذف دکمه پیام «این ربات متعلق به شما نیست»

باگ پارس `callback_data` بود: `"delbtn:<tid>:<bid>".partition(":")`
مقدار `tid` را برابر `"<tid>:<bid>"` می‌کرد. حالا با `split(":")` درست جدا می‌شود.

---

### عضویت اجباری اعمال نمی‌شد

بررسی عضویت **fail-open** بود: اگر ربات ادمین کانال نبود، تلگرام خطای
`CHAT_ADMIN_REQUIRED` می‌داد و کد خطا را نادیده می‌گرفت و کاربر را رد می‌کرد.
همچنین چک فقط در `/start` معنا داشت و با زدن دکمه‌ها دور زده می‌شد.

حالا:

- بررسی روی **هر پیام** انجام می‌شود، نه فقط `/start`
- رفتار **fail-closed** است: اگر ربات نتواند بررسی کند، دسترسی بسته می‌شود
- مالک ربات پیام هشدار با راهنمای رفع مشکل می‌گیرد (حداکثر هر ۳۰ دقیقه)
- هنگام تنظیم کانال، همان لحظه با کلاینت ربات فرزند چک می‌شود که ادمین هست یا نه
- ورودی‌های `@ch` / `ch` / `t.me/ch` / `https://t.me/ch` / `-100...` همه پذیرفته می‌شوند
- نتیجه‌ی بررسی ۶۰ ثانیه کش می‌شود تا فشار روی API کم شود
- مالک ربات از بررسی معاف است

### پشتیبانی ربات مادر پیامی به ادمین نمی‌رساند

ربات مادر اصلاً سیستم پشتیبانی نداشت (دکمه‌ی «☎️ پشتیبانی» در پنل فقط
پشتیبانی *ربات فرزند* را خاموش/روشن می‌کرد). حالا اضافه شد:

- دکمه‌ی «☎️ پشتیبانی» در منوی اصلی ربات مادر
- پیام کاربر برای **همه‌ی** ادمین‌های `.env` ارسال می‌شود
- ادمین با **ریپلای** روی پیام پاسخ می‌دهد
- جدول `dm_tickets` با کلید `chat_id + msg_id` تا با چند ادمین هم قاطی نشود

> ⚠️ ادمین باید حداقل یک‌بار ربات مادر را `/start` کرده باشد،
> وگرنه تلگرام اجازه‌ی ارسال پیام به او را نمی‌دهد.

---

### دکمه‌ی چندمحتوایی چطور کار می‌کند؟

جدول `button_items` آیتم‌های هر دکمه را با ترتیب نگه می‌دارد و
`buttons.caption_target` مشخص می‌کند متن به کدام آیتم بچسبد
(`-1` یعنی متن جداگانه فرستاده شود).

هنگام ارسال، ربات فرزند آیتم‌ها را به ترتیب می‌فرستد و متن را فقط یک بار
قرار می‌دهد. اگر آیتم هدف حذف شده باشد یا ارسالش شکست بخورد،
متن به‌صورت پیام مستقل فرستاده می‌شود تا گم نشود.

دکمه‌های تک‌محتوایی قدیمی بدون تغییر کار می‌کنند.

---

### 🤜 وظیفه اجباری چطور کار می‌کند؟ (نسخه‌ی جدید)

در نسخه‌های قبلی ربات سعی می‌کرد ری‌اکشن کاربر را از تلگرام تأیید کند؛ ولی
ری‌اکشن پست‌های کانال از نظر تلگرام ناشناس است و تأییدش به دسترسی ادمینیِ
خاص نیاز داشت که در عمل برای بیشتر سازنده‌ها کار نمی‌کرد. کل آن سیستم حذف شد.

مدل جدید (طبق درخواست صاحب ربات):
1. پنل ربات → `🤜 وظیفه اجباری` → «📢 کانال خواسته» و در صورت نیاز
   «⏱ ثانیه تاخیر» و «⏳ بازه تکرار» → «🟢 روشن کردن».
2. کاربر که فایلی را درخواست می‌کند، اول **پیام وظیفه** را می‌بیند
   (با دکمه‌ی «برو به کانال») — حداکثر هر **۲۴ ساعت** یک‌بار برای هر کاربر.
3. ربات ادعایی درباره‌ی انجام‌شدن وظیفه ندارد؛ بعد از **تاخیر تنظیم‌شده**
   (پیش‌فرض **۱۵ ثانیه**) محتوا خودکار ارسال می‌شود.
4. «📊 تعداد انجام وظیفه» در آمار، مجموع دفعات نمایش وظیفه را نشان می‌دهد.

> چون تأییدی وجود ندارد، ربات نیازی به ادمین‌بودن در کانال ندارد و پیام
> وظیفه روی `/start` هم نمایش داده می‌شود (منو بی‌تاخیر می‌آید؛ تاخیر فقط
> سرِ راهِ تحویل فایل است).

### 👥 زیرمجموعه‌گیری per-button چطور کار می‌کند؟

- قفل دعوت دیگر روی `/start` اعمال نمی‌شود؛ استارت همیشه کامل است.
- در پنل «🔘 دکمه‌ها»، هر دکمه یک دکمه‌ی **🎁** دارد (وقتی قفل روشن باشد 🔒):
  از آن‌جا می‌توانید قفل دعوت همان دکمه را روشن/خاموش و **تعداد لازم مخصوص
  همان دکمه** را تعیین کنید (۰ = تعداد پیش‌فرض پنل زیرمجموعه‌گیری).
- پنل «👥 زیرمجموعه‌گیری» **تعداد پیش‌فرض**، عکس و متن پیام دعوت را تعیین می‌کند.
- **fix باگ گزارش‌شده:** قبلاً اگر «کلید اصلی» خاموش بود یا هیچ تعدادی تنظیم
  نشده بود، قفلِ دکمه بی‌اثر می‌شد و کاربر بدون هیچ اخطاری محتوا می‌گرفت.
  حالا: قفل‌کردن هر دکمه، کلید اصلی را **خودکار روشن** می‌کند، اگر تعدادی
  تنظیم نشده باشد حداقل «۱ دعوت» لازم است، و خاموش‌کردن کلید اصلی وقتی
  دکمه‌ی قفل‌دار وجود دارد با **هشدار و تأیید دومرحله‌ای** انجام می‌شود.
- بعد از تکمیل دعوت‌ها، کاربر روی «🔄 بررسی کردم» می‌زند و محتوای همان دکمه
  **مستقیم** برایش ارسال می‌شود.

### ترتیب دروازه‌های دسترسی

هر پیام کاربر به این ترتیب بررسی می‌شود:
`⛔️ مسدودی → 📢 عضویت اجباری` و بعد به‌ترتیب: قفل دعوتِ همان دکمه →
🔑 پسورد فایل‌ها → 🤜 وظیفه اجباری (پیام + تاخیر) → محتوا (با 👁 بازدید و
دکمه‌ی 👍👎) + `🏁 پیام پایانی` و در صورت تنظیم، 🗑 حذف خودکار.
پیام وظیفه فقط روی `/start` و هنگام درخواست محتوا نمایش داده می‌شود، نه
سرِ هر پیام.

> ⚠️ **نکته‌ی استقرار:** بعد از به‌روزرسانی فایل‌ها، ربات مادر و همه‌ی
> ربات‌های فرزند باید یک‌بار خاموش/روشن شوند تا کد جدید روی فرزندها هم
> اعمال شود (فرزندها کد را هنگام استارت بار می‌کنند).

## ⚠️ نکات

- برای کانال اجباری، **ربات فرزند** باید ادمین آن کانال باشد.
- در broadcast بین هر پیام ۰٫۰۵ ثانیه تأخیر است تا محدودیت نرخ تلگرام رعایت شود.
- برای تعداد بسیار زیاد ربات (صدها)، بهتر است به Webhook یا اجرای چندپروسه‌ای مهاجرت کنید.
- فایل `.env` و پوشه‌ی `data/` را هرگز در گیت قرار ندهید (در `.gitignore` هست).
